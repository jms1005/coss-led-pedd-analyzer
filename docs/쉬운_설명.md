# 이 프로젝트, 쉽게 알아보기

> 처음 보는 사람을 위한 설명서입니다. 전자공학을 몰라도 읽을 수 있게 썼습니다.
> 정확한 수치와 회로 이론은 [계획서](../LED_PEDD_계획서_최종본.pdf)와
> [README](../README.md)에 있습니다.

---

## 1. 한 줄로 말하면

**컵에 담긴 액체가 무엇인지 맞히는 기계**를 만들고 있습니다.
그런데 카메라도, 센서도 쓰지 않고 **꼬마전구(LED) 4개**만으로 만듭니다.

물인지, 색소를 탄 물인지, 우유를 탄 물인지 — 기계가 화면에 답을 띄웁니다.

---

## 2. 왜 이게 신기한 일일까?

보통 이런 기계를 만들려면 **빛을 재는 전용 부품**(광센서)이 필요합니다.
비싸고, 구하기도 번거롭습니다.

우리는 그 부품을 **아예 쓰지 않습니다.** 대신 문방구에서도 파는
평범한 LED를 씁니다. 그래서 전체 부품값이 아주 쌉니다.

| | 보통의 방법 | 우리 방법 |
|---|---|---|
| 빛을 내는 것 | LED | LED 3개 |
| 빛을 재는 것 | 전용 광센서 (비쌈) | **LED 1개** |
| 값 | 비쌈 | 쌈 |

---

## 3. LED의 숨은 비밀

LED는 **빛을 내는** 부품으로 알려져 있습니다. 그런데 사실 LED에는
반대 능력도 있습니다.

> **LED에 빛을 비추면, 아주 약하지만 전기가 만들어집니다.**

태양광 패널의 아주아주 작은 버전이라고 생각하면 됩니다.
이 프로젝트는 바로 이 숨은 능력을 이용합니다.

- LED 3개 → 빛을 **내는** 담당 (빨강 · 초록 · 파랑)
- LED 1개 → 빛을 **느끼는** 담당 (검출용)

---

## 4. 전기는 어디서 시작해서 어디로 갈까?

### 딱 한 문장만 기억한다면

> **전기는 한 바퀴 돌아서 제자리로 돌아와야만 흐릅니다.**

미끄럼틀처럼 아래로 떨어져 사라지는 것이 아닙니다.
놀이터의 **뺑뺑이(회전목마)** 처럼 돌아서 출발점으로 와야 합니다.
길이 한 군데라도 끊기면 그 순간 **전체가 멈춥니다.**
뺑뺑이 바퀴를 하나 빼버린 것과 같습니다.

![빛을 내는 LED의 전기 흐름](../figures/flow/png/flow1.png)

### 순서대로 따라가 보기

빨간 LED를 켤 때 전기가 지나는 길입니다.

| 번호 | 어디서 | 무슨 일이 | 비유하면 |
|:--:|---|---|---|
| ① | USB 케이블 | 컴퓨터에서 **5V 전기**가 보드로 들어옵니다. 항상 대기 중입니다. | 물탱크가 가득 차 있음 |
| ② | 두뇌 칩 → D8 핀 | 칩이 D8 핀을 5V로 올립니다. 프로그램이 하는 일이 바로 이것입니다. | **수도꼭지를 연다** |
| ③ | 220Ω 저항 | 흐르는 전기의 양을 줄입니다. 없으면 LED가 타 버립니다. | 과속방지턱 |
| ④ | 빨간 LED | **긴 다리로 들어가 짧은 다리로 나오면서** 빛이 납니다. | 일방통행 도로 |
| ⑤ | GND(− 줄) | 다시 보드로 **돌아옵니다.** 여기까지 와야 ①~④가 실제로 작동합니다. | 결승선이자 출발선 |

```
USB 5V ─→ [칩 D8핀] ─→ [220Ω] ─→ [LED ▷|] ─→ GND ─┐
   ↑                                                │
   └────────────── 보드 안에서 이어짐 ───────────────┘
```

> **③ 저항이 왜 꼭 필요한가**
> LED는 "나는 이만큼만 받을래"라고 스스로 조절하지 못합니다. 주는 대로 다
> 받다가 타 버립니다. 그래서 밖에서 대신 막아 줘야 합니다.

> **④ 빛은 전기가 "지나갈 때" 납니다**
> LED가 전기를 삼켜서 빛으로 바꾸고 끝나는 것이 아닙니다.
> 들어온 만큼 계속 나가야 빛이 유지됩니다.

### 하나도 빠뜨리지 않고 — 전 구간 11단계

위 표는 큰 흐름이고, 실제로 전기가 지나는 곳을 하나도 빼지 않고 적으면
이렇게 됩니다. 배선을 확인할 때 이 순서대로 짚어 보세요.

| # | 지나는 곳 | 무슨 일이 |
|:--:|---|---|
| 1 | 칩 내부 5V | 대기 중인 전기. 아직 아무 데도 안 흐릅니다 |
| 2 | **D8 핀(PB0)** | 칩이 이 핀을 5V로 올립니다 = **수도꼭지 열림** |
| 3 | 점퍼선 | 보드에서 브레드보드로 건너갑니다 |
| 4 | 브레드보드 구멍 줄 | 같은 줄의 구멍끼리는 판 속에서 이어져 있습니다 |
| 5 | **220Ω 저항** | 흐르는 양을 줄입니다 |
| 6 | 저항 반대편 줄 | |
| 7 | **LED 애노드(긴 다리)** | 들어가는 문 |
| 8 | **LED 속 반도체 접합** | 여기서 **빛이 납니다** |
| 9 | **LED 캐소드(짧은 다리)** | 나오는 문 |
| 10 | 브레드보드 − 줄 → 점퍼선 | 돌아오는 길 |
| 11 | 보드 **GND 핀** → 칩 내부 → **USB 의 − 쪽** | 1번의 짝. 여기서 한 바퀴 완성 |

```
 시작 ─────────────────────────────────────────────── 끝
   ↓                                                  ↓
 USB 5V → D8핀 → 점퍼 → 220Ω → LED(긴다리▷|짧은다리) → GND → USB −
   └──────────────── 같은 전원의 양쪽 끝 ─────────────────┘
                        (그래서 "한 바퀴")
```

> **"끝"은 사실 "시작"과 같은 곳입니다.**
> GND 는 전기가 버려지는 쓰레기통이 아니라 **전원의 반대쪽 단자**입니다.
> 그래서 GND 줄을 빼면 출발점인 D8 쪽도 같이 죽습니다.
> 뺑뺑이의 반대편이 없으면 아예 못 도는 것과 같습니다.

### 색이 3개니까 길도 3개

똑같이 생긴 길이 색깔마다 하나씩, 모두 3개 있습니다.

| 색 | 출발하는 핀 | 길의 모양 |
|---|:--:|---|
| 빨강 | D8 | 저항 → LED → GND |
| 초록 | D9 | 저항 → LED → GND |
| 파랑 | D10 | 저항 → LED → GND |

**길이 3개면 수도꼭지도 3개**입니다. 칩이 D8만 열면 빨강만, D9만 열면 초록만
켜집니다. 그래서 "빨강 재고 → 끄고 → 초록 재고 → 끄고 → 파랑 재고"를
순서대로 할 수 있습니다.

### 초보자가 실제로 가장 많이 틀리는 두 가지

**1. GND 줄을 안 꽂았다**

"전기를 줬는데 왜 안 켜지지?" 하는 경우의 대부분입니다.
**돌아오는 길**을 안 만들어 준 것입니다. 뺑뺑이를 반쪽만 만든 셈이라 아예
돌지 않습니다. 부품이 고장 난 것이 아닙니다.

**2. LED를 거꾸로 꽂았다**

LED는 **일방통행 도로**입니다. 긴 다리(+) → 짧은 다리(−) 방향으로만 전기가
지나갑니다. 거꾸로 꽂으면 전기가 막혀서 불이 안 켜집니다. 발광 LED는 220Ω
저항이 지켜 주기 때문에 **그냥 안 켜질 뿐, 망가지지는 않습니다.** 방향만
바꿔 꽂으면 됩니다.

> **주의 — 검출 LED(D7)는 이야기가 다릅니다.**
> 검출 LED에는 저항이 없습니다. 거꾸로 꽂으면 **과전류가 흘러 소자가 상할 수
> 있습니다.** 그리고 다리 길이로 방향을 판별하지 마세요. 실제 조립에서 두 번
> 반대로 꽂았습니다. 판별 방법은
> [`docs/실수_방지_체크리스트.md`](실수_방지_체크리스트.md)를 보세요.

> **재미있는 점**
> 이 프로젝트에서 **검출용 LED는 일부러 거꾸로 꽂습니다.**
> "막혀서 전기가 고인다"는 성질을 오히려 이용하기 때문입니다. 다음 장에서
> 설명합니다.

## 5. 그럼 빛은 어떻게 "재는" 걸까?

여기가 이 프로젝트에서 가장 중요한 부분입니다.

검출용 LED는 **일부러 거꾸로 꽂습니다.** 실수가 아니라 의도입니다.
그리고 두 단계로 나눠서 측정합니다.

![검출 LED의 충전과 방전](../figures/flow/png/flow2.png)

### 1단계 — 물컵에 물 채우기 (충전)

칩이 D7 핀을 5V로 밀어 넣습니다. 그런데 LED가 거꾸로 꽂혀 있어서
**전기가 통과하지 못합니다.** 갈 곳이 없어진 전기는 LED 안에 **고입니다.**

물컵에 물을 가득 채우는 것과 같습니다. 걸리는 시간은 **0.0001초**입니다.

### 2단계 — 새는 시간 재기 (방전)

이제 칩이 D7 핀의 문을 닫습니다(핀을 '입력'으로 바꿉니다).
고인 전기는 이제 나갈 길이 없습니다. 가만히 두면 그대로 있어야 합니다.

**그런데 빛이 들어오면 이야기가 달라집니다.**
LED가 빛을 전기로 바꾸기 시작하고, 고여 있던 전기가 조금씩 빠져나갑니다.

> 컵에 구멍이 뚫린 셈입니다.
> **빛이 밝을수록 구멍이 크고, 물이 빨리 빠집니다.**

### 그래서 무엇을 재는가

전기가 **1.1V 아래로 내려가는 순간**을 칩 안의 '비교기'라는 부품이 알아채고
스톱워치를 멈춥니다.

| 빛의 밝기 | 전기가 빠지는 속도 | 잰 시간 |
|---|---|---|
| 밝음 | 빠르다 | **짧다** |
| 어두움 | 느리다 | **길다** |

이렇게 해서 **"밝기"라는 눈에 보이는 것을 "시간"이라는 숫자로** 바꿉니다.
컴퓨터는 숫자만 다룰 수 있으니까요.

## 6. 액체를 어떻게 알아맞힐까?

빛이 액체를 지나갈 때, 액체는 **빛의 일부를 삼킵니다.**
그리고 액체마다 삼키는 양이 다릅니다.

- 맑은 물 → 빛을 거의 안 삼킴 → 검출 LED에 빛이 많이 도착 → **시간 짧음**
- 우유 탄 물 → 빛을 많이 삼킴 → 빛이 조금 도착 → **시간 김**

![빛과 정보의 흐름](../figures/flow/png/flow3.png)

### 색깔 하나로는 부족합니다

색을 하나만 쓰면 **서로 다른 액체가 같은 값으로 나오는 짝**이 생깁니다.

빨간 빛 하나로만 잰다고 해봅시다.

| 액체 | 빨간 빛으로 잰 시간 |
|---|---|
| 맑은 물 | 짧음 |
| **빨간 색소물** | **짧음** ← 빨간 색소는 빨간 빛을 잘 통과시킵니다 |

두 값이 같습니다. 기계가 가진 숫자가 하나뿐이라 **구분할 방법이 없습니다.**

그래서 **빨강 · 초록 · 파랑을 하나씩 켜서 세 번** 잽니다.
그러면 액체마다 숫자 **세 개**가 나옵니다. 이걸 **광학 지문**이라고 부릅니다.

| 액체 | 빨강 | 초록 | 파랑 |
|---|:--:|:--:|:--:|
| 맑은 물 | 짧음 | 짧음 | 짧음 |
| 빨간 색소물 | 짧음 | **김** | **김** |
| 우유물 | 김 | 김 | 김 |

빨강 칸만 보면 1행과 2행이 같지만 **초록·파랑 칸에서 갈립니다.**
숫자 세 개를 묶어서 보면 어느 두 줄도 겹치지 않습니다.

> 사람도 마찬가지입니다. 키만으로는 누구인지 못 알아보지만
> 키·몸무게·발 크기를 함께 보면 구분됩니다.
> **재는 항목을 늘리면 구분력이 올라갑니다.**

> 위 표는 **원리를 보여주는 예시**입니다. 하드웨어를 아직 조립하지 않아서
> 실제로 잰 값이 아닙니다. 진짜 값은 측정한 뒤 `data/` 폴더에 들어갑니다.

빨간 색소물이 빨간 빛은 잘 통과시키고 초록·파랑은 많이 삼키는 것처럼,
사람 지문처럼 액체마다 무늬가 다릅니다.
기계는 **미리 배워둔 지문**과 견줘서 가장 닮은 것을 답으로 내놓습니다.

### 왜 하필 빨강 · 초록 · 파랑일까?

- **눈에 보이는 빛을 골고루 나눠 덮습니다.** 파랑(짧은 파장) · 초록(중간) ·
  빨강(긴 파장). 세 지점만 찍어도 전체 경향을 짐작할 수 있습니다.
- **검출 LED(빨강)가 셋 다 받을 수 있습니다.** LED 는 **자기가 내는 빛과
  같거나 그보다 파장이 짧은(= 에너지가 센) 빛**만 느낍니다. 빨강이 가장
  긴 파장이라 빨강·초록·파랑이 전부 이 조건에 듭니다. 파란 LED 로 검출하면
  파랑밖에 못 받습니다.
  자세한 이유는 9장 "왜 검출 LED 는 꼭 빨간색일까?"에 있습니다.
- **싸고 어디서나 구할 수 있습니다.**

### 왜 4개, 5개는 아닐까?

색을 늘릴수록 구분은 잘 됩니다. 하지만 **핀을 더 쓰고, 측정 시간이 늘고,
부품값도 오릅니다.** 액체 3종류를 가르는 데는 3색이면 충분해서 3개로
정했습니다. 나중에 더 비슷한 액체를 구분해야 한다면 그때 색을 늘리면 됩니다.

## 7. 어떻게 쓰나요?

버튼 하나로 다 됩니다.

```
버튼을 길게(2초) 누른다  →  학습 모드
                            증류수 → 색소물 → 우유물 순서로 하나씩 재서 외운다

버튼을 짧게 누른다       →  측정
                            지금 들어 있는 액체가 뭔지 맞힌다  →  화면에 표시
```

화면에는 영어로 나옵니다. `DISTILLED WATER`(증류수) · `DYE WATER`(색소물) ·
`MILK`(우유물) 셋 중 하나입니다.

전원을 처음 켜면 화면에 `NOT TRAINED`(아직 안 배웠음)가 뜹니다.
**먼저 길게 눌러서 가르쳐 줘야** 맞힐 수 있습니다.
한 번 배운 내용은 전원을 꺼도 기억합니다.

## 8. 로그 읽는 법 — 화면 대신 숫자로 볼 때

7장은 완성된 기계(Phase 4)의 사용법입니다. 그 전 단계인 **Phase 1 · 2** 에서는
OLED 화면이 없고, USB 로 이어진 컴퓨터에 **숫자가 줄줄이 찍힙니다.**
그 숫자를 읽는 법입니다.

터미널 프로그램을 **38400 bps, 8N1** 로 열면 이렇게 나옵니다.

```
# PEDD Phase 1 log / 1 tick = 500ns
seq,ch,status,ticks,us,ovf
0,DARK,OK,41230,20615,0
0,R,OK,8120,4060,0
1,DARK,OK,41180,20590,0
1,R,OK,8095,4047,0
```

> 위 숫자는 **읽는 법을 보여주는 예시**입니다. 실제로 잰 값이 아닙니다.

---

### ticks — 이 기계가 실제로 재는 값

나머지 칸은 곁다리이고, **진짜 값은 이것 하나**입니다.

검출 LED 에 전기를 채워 놓고, 빛 때문에 그것이 새어 나가
**1.1V 아래로 떨어질 때까지 걸린 시간**입니다.

`tick` 은 칩 안의 스톱워치가 세는 한 칸입니다.

> **1 tick = 500ns = 0.0000005 초**

초로 쓰면 0 이 너무 많아서 "몇 칸이었나"로 셉니다.
자로 재면서 미터 대신 밀리미터로 세는 것과 같습니다.

| ticks | 뜻 |
|---|---|
| **작다** | 빨리 빠졌다 → **빛이 밝았다** → 액체가 빛을 안 삼켰다 |
| **크다** | 천천히 빠졌다 → **빛이 어두웠다** → 액체가 빛을 많이 삼켰다 |

> ⚠️ **숫자가 크다고 빛이 센 것이 아닙니다. 정반대입니다.**
> 재는 것이 "밝기"가 아니라 "새는 데 걸린 시간"이기 때문입니다.

바로 옆 `us` 칸은 같은 값을 마이크로초로 바꿔 준 것뿐입니다.
`41230 ticks × 0.5 = 20615 us`.

---

### DARK / R — 몇 번째 측정인지 구분하는 이름표

`ch` 칸에 들어갑니다. 한 사이클에 두 번 재는데, 그 둘을 구별합니다.

| 이름 | 발광 LED | 무엇을 재나 |
|---|---|---|
| **DARK** | **전부 꺼짐** | 빛을 안 쐈는데도 생기는 값 = 환경광 + 암전류 |
| **R** | **빨강 켜짐** | 우리가 쏜 빨간 빛이 액체를 통과해 도착한 양 |

**DARK 를 왜 재는가** — 챔버를 아무리 막아도 빛은 조금 샙니다. 부품 자체도
아주 작은 전기를 흘립니다. 이 "가만히 있어도 생기는 값"을 모르면 우리가 쏜
빛의 효과만 따로 떼어낼 수 없습니다.
**저울에 빈 그릇을 먼저 올려 0점을 잡는 것**과 같습니다.

```
DARK 41230  ← 아무것도 안 쐈을 때
R     8120  ← 빨간 빛 쐈을 때
              차이가 클수록 "빛이 잘 도착했다"
```

두 값을 **빼서** 쓰기 때문에 방 조명이 조금 달라져도 결과가 덜 흔들립니다.

Phase 2 부터는 `G`(초록) · `B`(파랑)가 늘어 `DARK → R → G → B` 네 줄이
나옵니다. 그 세 개가 6장의 **광학 지문**입니다.

---

### TIMEOUT — 너무 오래 걸려서 포기했다는 뜻

`status` 칸에 `OK` 아니면 `TIMEOUT` 이 찍힙니다.

| 값 | 뜻 |
|---|---|
| `OK` | 시간 안에 1.1V 아래로 떨어졌다 = **정상 측정** |
| `TIMEOUT` | **약 2초**를 기다려도 안 떨어졌다 = 포기하고 다음으로 넘어감 |

빛이 아예 안 들어오면 전기가 거의 안 새서 몇 분이 걸릴 수도 있습니다.
그러면 프로그램이 거기서 멈춰 버리므로 2초까지만 기다리고 끊습니다.
**전화를 무한정 붙들지 않고 "안 받네" 하고 끊는 것**과 같습니다.

빛을 일부러 완전히 막고 `TIMEOUT` 이 뜨는지 보는 것은
**정상 동작을 확인하는 시험 항목**입니다(Phase 1 측정 순서 5번).

---

### ovf — 스톱워치가 몇 바퀴 돌았나

맨 끝 칸입니다. 스톱워치는 65536 칸까지만 세고 0 으로 돌아갑니다.
넘어간 횟수를 따로 세어 둔 것이 `ovf` 입니다.
**초침이 60 에서 0 으로 돌아가면 분침이 1 올라가는 것**과 같습니다.

- `ovf 0` → 한 바퀴 안에 끝남 (대부분 여기)
- `ovf 61` → 61 바퀴 = 약 2초 = TIMEOUT 지점

---

### 한 줄 통째로 읽어보기

```
0,R,OK,8120,4060,0
│ │ │   │    │   └ ovf   : 스톱워치 안 넘침
│ │ │   │    └──── us    : 4060 마이크로초 = 0.004 초
│ │ │   └───────── ticks : 8120 칸 걸렸다   ← 진짜 값
│ │ └───────────── status: 정상 측정됨
│ └─────────────── ch    : 빨간 LED 켜고 잰 것
└───────────────── seq   : 0 번째 사이클
```

> "0 번째 측정에서, 빨간 빛을 켜고 쟀더니, 정상적으로 0.004 초 만에
> 전기가 다 빠졌다."

DARK 가 20615us 인데 R 이 4060us 이므로 **빛이 도착해서 5배쯤 빨리
빠진 것**입니다. 발광·검출 LED 가 제대로 동작하고 있다는 뜻입니다.

---

### 이상하면 여기를 봅니다

**눈으로 판정하지 마세요.** 발광 LED 는 한 번에 **몇 ms 정도**만 켜졌다
꺼지기를 반복해서(안정화 5ms + 방전 측정 시간) 켜졌는지 알아보기 어렵고,
검출 LED 는 원래 끝까지 안 켜집니다. 판정은 이 표로 합니다.

> 예외 하나. 빛이 전혀 안 들어와 `TIMEOUT` 이 나는 상황에서는 그 LED 가
> **2초 동안** 켜져 있습니다. 오래 켜져 있는 것이 오히려 이상 신호입니다.

| 로그 증상 | 원인 | 조치 |
|---|---|---|
| `ticks` 가 **0~1 로 고정** | 검출 LED **극성 반대** | 그대로 180° 돌려 꽂기 |
| **전 채널 `TIMEOUT`** (ovf 61) | 검출 LED **미접속·단선** | 다리와 D7 점퍼를 다시 꽂기 |
| `R` 채널만 `TIMEOUT` | 검출 LED 가 청색·녹색 | 적색 검출 LED 로 교체 |
| `DARK` 와 `R` 이 거의 같음 | 발광 LED 미점등 · 빛 경로 어긋남 | D8 배선과 LED 방향 확인, 두 LED 를 마주 보게 |
| 아무것도 안 나옴 | 업로드 실패 · 보드레이트 불일치 | 38400 확인, `01_blink` 부터 다시 |

> ⚠️ **위 두 행은 증상이 정반대이므로 원인도 정반대입니다.**
> `0~1 tick` 은 "너무 빨리 끝남"이고 `TIMEOUT` 은 "끝나지 않음"입니다.
> 두 행을 바꿔 읽으면 멀쩡한 배선을 뒤집게 되니 증상을 먼저 확인하세요.

자세한 진단은 [`docs/실수_방지_체크리스트.md`](실수_방지_체크리스트.md) 에
있습니다.

## 9. 부품 소개

| 부품 | 몇 개 | 하는 일 |
|---|:--:|---|
| 아두이노 우노 보드 | 1 | 두뇌. 핀을 켜고 끄고, 시간을 재고, 판단한다 |
| 발광 LED (빨강·초록·파랑) | 3 | 액체에 빛을 비춘다 |
| **검출 LED (빨강)** | 1 | 도착한 빛의 양을 시간으로 바꾼다 |
| 저항 (220Ω부터) | 3 | 발광 LED에 전기가 너무 많이 흐르지 않게 막는다 |
| 버튼 | 1 | 측정 시작 / 학습 시작 |
| OLED 화면 | 1 | 결과를 보여준다 |
| 큐벳 | 여러 개 | 액체를 담는 작은 투명 통 |
| 차광 챔버 | 1 | 바깥 빛을 막는 검은 상자 |
| 브레드보드 · 점퍼선 | — | 납땜 없이 부품을 잇는 판과 전선 |

> **저항값이 "220Ω부터"인 이유**
> 220Ω은 시작값입니다. 실제로 재보고 빛이 너무 세면 값을 올리고(330·470·1k),
> 너무 약하면 내립니다. 그래서 여러 값을 함께 사둡니다.

> **왜 차광 챔버가 필요할까?**
> 형광등이나 햇빛이 조금만 새어 들어와도 검출 LED가 그 빛까지 세어 버립니다.
> 그러면 액체를 바꿔도 값이 안 변합니다. 그래서 검은 상자 안에서 측정합니다.

> **왜 검출 LED는 꼭 빨간색일까?**
> LED는 **자기가 내는 빛과 같거나 그보다 파장이 짧은(= 에너지가 같거나 센)
> 빛**만 느낄 수 있습니다. 빨강이 셋 중 가장 긴 파장이므로, 빨간 LED는
> 빨강·초록·파랑을 전부 느낍니다. 반대로 파란 LED는 파랑밖에 못 느낍니다.
> 검출 LED 하나로 세 가지 색을 다 받아야 하니 **빨간색이어야 합니다.**
> 파란색을 사면 측정이 아예 안 됩니다.
>
> 다만 **빨강은 딱 경계에 걸려 있어 가장 약하게 느껴집니다.** Red 채널의
> 값이 초록·파랑보다 크게(= 어둡게) 나오는 것은 고장이 아니라 정상입니다.
> 아예 `TIMEOUT` 이 뜬다면 그때는 검출 LED 색을 의심하세요.

## 10. 어려운 말 사전

| 말 | 쉬운 뜻 |
|---|---|
| MCU / ATmega328P | 아주 작은 컴퓨터 칩. 이 기계의 두뇌 |
| 핀 (D7, D8, A4 …) | 칩 밖으로 나온 다리. 전기가 드나드는 문 |
| GND (그라운드) | 전기가 돌아오는 길. 모든 회로의 공통 출발선 |
| 5V, 1.1V | 전기를 미는 힘의 세기. 숫자가 클수록 세다 |
| 저항 (220Ω) | 전기가 지나가기 힘들게 만드는 부품. 과속방지턱 |
| 애노드 / 캐소드 | LED의 긴 다리 / 짧은 다리 |
| 충전 / 방전 | 전기를 채우기 / 전기가 빠져나가기 |
| PEDD | 이 측정 방식의 이름. "LED로 빛을 내고 LED로 받는다"는 뜻 |
| 광학 지문 | 한 액체에서 나온 숫자 세 개 묶음 |
| 펌웨어 | 칩 안에 넣는 프로그램 |
| 브레드보드 | 납땜 없이 부품을 꽂아 잇는 구멍 뚫린 판 |
| tick | 칩 스톱워치의 한 칸. 1 tick = 500ns |
| ticks | 전기가 다 빠지는 데 걸린 시간. **이 기계가 재는 진짜 값** |
| DARK / R | 발광 LED 를 끄고 잰 것 / 빨강을 켜고 잰 것 |
| TIMEOUT | 약 2초를 기다려도 안 끝나서 포기했다는 표시 |
| ovf | 스톱워치가 한 바퀴(65536칸) 넘어간 횟수 |
| bps (38400) | 컴퓨터와 보드가 숫자를 주고받는 속도. 서로 같아야 한다 |

## 이 문서의 그림은 어떻게 만드나

그림 3장은 손으로 그린 것이 아니라 스크립트가 만듭니다.
핀 번호가 바뀌면 그림도 같이 고쳐야 하므로, 값을 한곳에 모아 두었습니다.

```sh
sh tools/make_flow_png.sh    # SVG 3장 + PNG 3장까지 한 번에
```

SVG 와 PNG 를 둘 다 두는 이유가 있습니다.

| 형식 | 쓰는 곳 | 이유 |
|---|---|---|
| PNG | 이 문서, GitHub 웹 | 어느 컴퓨터에서 봐도 글꼴이 같게 나온다 |
| SVG | 인쇄, 발표 슬라이드 | 벡터라서 아무리 키워도 글자가 안 흐려진다 |

핀 배정을 바꾸려면 **펌웨어를 먼저** 고치세요
(`firmware/common/pedd.c`). 그림은 그다음입니다.
