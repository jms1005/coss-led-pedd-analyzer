## 2. 입력이 무엇인지부터

`classify.c` 는 하드웨어를 전혀 만지지 않는다. 입력은 `pedd.c` 가 넘겨준
숫자 4개뿐이다.

| 입력 | 의미 |
|---|---|
| `t_dark` | 발광 LED 를 전부 끄고 잰 방전 시간 |
| `t_r`, `t_g`, `t_b` | R/G/B 를 각각 켜고 잰 방전 시간 |

- 단위는 **틱, 1틱 = 500ns** (16MHz, 프리스케일러 /8) — `pedd.h`
- **`t == 0` 은 TIMEOUT** 이다. "제한 시간 안에 방전이 안 끝났다"
  = "빛이 거의 안 왔다"

> **질문 대비** — "왜 이 파일만 `<avr/io.h>` 를 안 넣었나요?"
> → PC 에서 그대로 컴파일해 단위 테스트하려고. `tests/test_classify.c` 가
> 그 파일이다. 물어보면 점수를 따는 대목이니 반드시 준비할 것.

## 3. 4단계 흐름

### 1단계 — 시간을 밝기로 뒤집는다 (`conductance`)

```
G = 1,000,000,000 / t
```

빛이 셀수록 전하가 빨리 빠져서 `t` 가 작아진다. 즉 t 는 밝기에
**반비례**하므로 역수를 취하면 밝기에 비례하는 값이 된다.

- **왜 1 이 아니라 1e9 를 나누나?** 정수만 쓰려고. `1/t` 를 정수로 하면
  전부 0 이 된다. 큰 상수를 나눠야 유효 자릿수가 남는다.
- **오버플로는 안전한가?** t 최소 1 일 때 G = 1e9, 세 채널 합 최대
  3e9 < 4.29e9 (uint32 상한). 안전하다.
- `t == 0`(타임아웃)이면 G = 0.

### 2단계 — 암전류를 뺀다

```
I[k] = G[k] - G_dark      (음수가 되면 0)
```

빛이 하나도 없어도 반도체 안에서 전하가 조금씩 샌다. 이것을 **암전류**라
한다. 세 채널이 이 몫을 똑같이 깔고 있으므로 빼 주어야 "LED 빛 때문에
생긴 순수한 양"만 남는다.

> **함정** — `uint32_t` 는 부호가 없어서 빼다가 음수가 되면 40억대의 거대한
> 값으로 뒤집힌다. 그래서 `(g > g_dark) ? (g - g_dark) : 0` 로 크기를 먼저
> 비교한다. 이건 물어보면 바로 답할 수 있어야 한다.

빼고 난 합이 `CLASSIFY_MIN_SIGNAL`(3000) 미만이면 **`LOW_SIGNAL` 로 끊고
반환한다.** 광 경로가 막혔거나 LED 극성이 반대인 상황이고, 이 상태로
정규화하면 의미 없는 숫자가 나오기 때문이다.

### 3단계 — 비율만 남긴다 (정규화) ← 핵심

```
n[k] = I[k] × 1000 / sum       (세 채널 합 = 약 1000)
```

**왜 비율인가:** LED 를 큐벳에 조금 가깝게 놓으면 세 채널이 *다 같이*
밝아진다. 하지만 액체가 같다면 채널 *사이의 비율*은 그대로다. 절대값 대신
비율을 쓰면 거리·전압 흔들림에 판정이 흔들리지 않는다.

> 예: (800, 200, 200) 과 (400, 100, 100) 은 밝기가 2배 차이지만
> 정규화하면 둘 다 (666, 166, 166) 이 되어 같은 지문으로 취급된다.

**앞의 시프트 루프는 왜 있나** (자주 물어본다):

```c
while (sum > CLASSIFY_SHIFT_LIMIT) {   /* 4,000,000 */
  i[k] >>= 1;                          /* 세 채널을 다 같이 절반으로 */
}
```

`I[k] * 1000` 이 32비트를 넘칠 수 있어서 미리 줄인다. **세 채널을 함께**
줄이므로 비율(= 지문)은 보존된다. 쓸 것은 비율뿐이라 절대 크기가 작아져도
상관없다.

### 4단계 — 가장 가까운 기준점 고르기 (`classify_match`)

지문 `(n0, n1, n2)` 를 **3차원 공간의 점 하나**로 본다. 학습 때 저장해 둔
액체별 기준점(**중심점, centroid**)이 3개 있고, 그중 제일 가까운 것의
이름을 답으로 낸다. 이것이 **최근접 중심점(nearest centroid)** 방식이다.

```
d² = Σ (n[k] - centroid[c][k])²
```

- **제곱근을 왜 안 씌우나?** 크기 *비교*만 하기 때문이다. 제곱근은 순서를
  바꾸지 않는다. 계산을 통째로 아낄 수 있다.
- **`threshold_d2` 는 무엇인가?** 제일 가까운 점이라도 너무 멀면
  **`-1`(미상)** 을 반환한다. 학습하지 않은 액체를 넣었을 때 아무 이름이나
  붙이지 않기 위한 안전장치다.
- `dist`(제곱근)는 **화면 표시용으로만** 계산한다. 사람이 감을 잡기 쉬우라고.

## 4. 숫자로 한 번 걸어보기

입력: `t_dark` = 타임아웃, `t_r` = 980, `t_g` = 1204, `t_b` = 1510

| 단계 | R | G | B |
|---|---|---|---|
| ① 컨덕턴스 `1e9/t` | 1,020,408 | 830,564 | 662,251 |
| ② 암전류 보정 (G_dark = 0) | 그대로 | 그대로 | 그대로 |
| 합 | \- | 2,513,223 (< 4e6 → 시프트 없음) | \- |
| ③ 정규화 | **406** | **330** | **263** |

합 = 999. 정수 나눗셈 내림 때문에 정확히 1000 이 아니라 997~1000 이 된다.

중심점이 (400, 330, 270) 이라면 d² = 6² + 0² + 7² = **85**.
이 값이 `threshold_d2` 보다 작으면 그 클래스로 판정한다.

## 5. `classify_isqrt` — 왜 `sqrt()` 를 안 쓰나

뉴턴법(바빌로니아법)이다. `x` 와 `v/x` 의 평균을 새 `x` 로 삼기를 반복한다.
x 가 정답보다 크면 `v/x` 는 정답보다 작으므로 평균은 항상 정답 쪽으로
다가간다. 몇 번만 돌면 수렴한다.

**`sqrt()` 를 쓰지 않는 진짜 이유:** 그것은 부동소수점 함수라서, 쓰는 순간
**소프트웨어 부동소수점 라이브러리가 통째로 링크되어 Flash 를 1.5~3KB
잡아먹는다.** 이 파일 전체를 정수로 쓴 이유도 같다.

> 아마 이 프로젝트에서 가장 "임베디드다운" 대답이다. 꼭 준비할 것.

## 6. 예상 질문과 답

**Q. `classify.c` 가 학습도 하나요?**
→ 아니다. **판정만** 한다. 학습(중심점 계산)은 `main.c` 쪽에서 하고, 결과는
`store.c` 가 EEPROM 에 저장한다. `classify_match` 는 그 중심점을 인자로
받기만 한다. 계산과 저장을 분리했다.

**Q. 왜 머신러닝(k-NN, SVM 등)을 쓰지 않았나요?**
→ ATmega328P 급에서 돌아야 하고 클래스가 3개뿐이다. 최근접 중심점은 곱셈
9번, 뺄셈 9번이면 끝나고 RAM 도 중심점 18바이트면 된다. 문제 크기에 맞는
가장 단순한 방법을 골랐다.

**Q. 이 방식의 한계는 무엇인가요?** *(솔직하게 답하면 오히려 점수)*
→ 세 가지가 있다.
1. **정규화하면서 절대 밝기 정보를 버린다.** 색은 같은데 농도만 다른 두
   액체는 구분되지 않는다.
2. **최근접 중심점은 클래스마다 퍼진 정도가 비슷하다고 가정한다.** 한
   클래스만 값이 크게 흔들리면 그쪽으로 잘못 끌려간다. (마할라노비스 거리를
   쓰면 개선되지만 그러면 정수 연산으로 끝나지 않는다.)
3. **`threshold_d2` 를 사람이 정해야 한다.** 너무 크면 아무거나 다 인식하고,
   너무 작으면 전부 미상이 된다.

**Q. 테스트는 어떻게 했나요?**
→ 하드웨어 의존을 뺀 순수 계산 모듈이라 PC 에서 `sh tools/run_host_tests.sh`
로 바로 돌린다. 균등 입력, 합 정규화, 순서 보존 같은 성질을 각각 검증한다.
보드에 올려 액체를 담고 버튼을 누르는 것보다 훨씬 빠르고, "코드가 틀린 것"과
"측정이 흔들린 것"을 구별할 수 있다.

## 7. 연습 방법

3단계 표(시간 → 밝기 → 비율 → 이름)만 그려 놓고 **5분 설명**을 두세 번
소리 내어 해 본다.

세부 상수(1e9, 1000, 3000)는 외우지 않아도 되지만, 아래 네 개는 즉답이
나와야 한다. 실제로 파고드는 것은 상수가 아니라 이 네 개다.

- 왜 **역수**인가
- 왜 **비율**인가
- 왜 **제곱근을 안 씌우나**
- 왜 **float 를 안 쓰나**
