# Phase 4 설계 — 온칩 분류 및 시스템 통합

- 작성일: 2026-09-03
- 대상: 계획서 4.4절 "Phase 4 — 온칩 분류 구현 및 시스템 통합"
- MCU: ATmega328P (16MHz), Microchip Studio / avr-gcc, 베어메탈

> **읽는 법.** 🟡 표시가 붙은 절은 **사용자가 확인해야 하는 부분**입니다.
> 화면에 실제로 뜨는 문구, 시료 이름, 버튼 순서처럼 틀리면 시연에서
> 어색해지는 것들입니다. 나머지는 구현 책임 영역이니 훑고 넘어가도 됩니다.
>
> 📊 표시는 **PPT에 그대로 쓸 수 있는 내용**입니다.

## 1. 목적

Phase 1~3이 "측정값을 PC로 보내는 실험 장비"였다면, Phase 4는 **PC 없이
혼자 판정까지 하는 완제품**이다. 계획서 1.4절의 데모 시나리오를 완성한다.

```
버튼 → R/G/B 스캔 → 암전류 보정 → 정규화 → 최근접 중심점 분류 → OLED + UART
```

요강이 요구하는 "디스플레이·스위치 등 외부 부품과 데이터를 주고받는 회로"를
충족하는 단계이기도 하다.

## 2. 확정된 요구사항

| 항목 | 결정 | 근거 |
|---|---|---|
| 기준점 주입 | **온디바이스 학습 모드** | PC 없이 현장 재보정. 시연 요소 |
| 분류 대상 | **3종 + UNKNOWN** | 오분류를 숨기지 않음. 혼동표 작성에 필요 |
| 조작 | **버튼 1개, 짧게/길게** | 핀 수 채점에 유리. 회로도 수정 불필요 |
| 화면 | **판정 + 3채널 값 + 거리** | 심사위원이 측정 사실을 화면으로 확인 |
| 연산 | **정수 고정소수점** | Flash·처리시간 채점 항목 (4.4.3절) |

## 3. 핀 배치 📊

총 **9핀** 사용. 기존 5핀 + 신규 4핀.

| 핀 | 포트 | 용도 | 신규 |
|---|---|---|:---:|
| D8 / D9 / D10 | PB0 / PB1 / PB2 | 발광 LED R / G / B | |
| D7 | PD7 (**AIN1**) | 검출 LED 캐소드 | |
| D1 | PD1 (TXD) | UART 송신 | |
| D2 | PD2 | 택트 스위치 | ✔ |
| A4 / A5 | PC4 / PC5 | I²C SDA / SCL | ✔ |
| D13 | PB5 | 사이클 시간 측정 토글 | ✔ |

- **PD7은 변경 불가.** Analog Comparator의 음극 입력(AIN1)이 이 핀에 고정.
- **PB5는 보드 내장 LED와 공유.** 측정 중 점등 표시를 겸하므로 부품이 늘지
  않는다. 계획서 4.4.2절의 "여유 GPIO 토글 후 오실로스코프로 펄스 폭 측정"이
  이 핀이다.
- 스위치는 **INT0 인터럽트를 쓰지 않고 폴링 + 디바운스**로 처리한다.
  인터럽트는 Timer1 입력 캡처 타이밍에 지터를 줄 수 있고, 측정 정밀도가
  이 프로젝트의 핵심이기 때문이다.

## 4. 모듈 구성 📊

```
common/
  pedd.c/h      (기존)  방전 시간 측정
  uart.c/h      (기존)  시리얼 송신
  i2c.c/h       [신규]  TWI 마스터 — TWBR/TWCR/TWDR/TWSR 직접 제어
  ssd1306.c/h   [신규]  OLED 초기화 + 텍스트 출력
  font6x8.h     [신규]  폰트 테이블 (Flash 상주)
  button.c/h    [신규]  디바운스 + 짧게/길게 판정
  classify.c/h  [신규]  보정 · 정규화 · 최근접 중심점
  store.c/h     [신규]  EEPROM 접근 — EECR/EEDR/EEAR 직접 제어
04_phase4/
  main.c        [신규]  상태머신
```

**기존 `common/` 파일은 수정하지 않는다.** phase1·phase2가 계속 빌드되어야
실험을 병행할 수 있다.

각 모듈의 계약:

| 모듈 | 하는 일 | 의존 |
|---|---|---|
| `i2c` | 바이트 단위 TWI 전송. 주소·start·stop | 없음 |
| `ssd1306` | 커서 위치에 문자열 출력, 화면 지우기 | `i2c`, `font6x8` |
| `button` | 20ms 폴링, `NONE`/`SHORT`/`LONG` 반환 | 없음 |
| `classify` | 틱 4개 → 지문 3개 → 클래스 + 거리 | 없음 (순수 계산) |
| `store` | 중심점 묶음 read/write, 유효성 검사 | 없음 |
| `main` | 상태머신, 화면 구성, UART 로깅 | 전부 |

`classify`가 하드웨어에 의존하지 않는 **순수 계산 모듈**인 점이 중요하다.
PC에서 같은 로직을 돌려 검증할 수 있어야 하기 때문이다 (11절 참조).

### 4.1 프레임버퍼를 쓰지 않는 이유

SSD1306 드라이버는 보통 프레임버퍼를 SRAM에 둔다. 128×64÷8 = **1,024바이트**로
ATmega328P SRAM 2KB의 **절반**이라 채택할 수 없다.

대신 **페이지 주소 모드로 화면에 직접 쓴다.** 문자 하나를 그릴 때마다 폰트
6바이트를 Flash에서 읽어 I²C로 바로 밀어넣는다. SRAM 사용이 사실상 0이다.
표시 내용이 텍스트뿐이고 부분 갱신이 필요 없어 이 방식으로 충분하다.

### 4.2 폰트 범위 🟡

ASCII `0x20`(공백) ~ `0x5F`(`_`) **64자만** 넣는다. 64 × 6 = **384바이트**.

> **결과: 화면 문구는 전부 대문자다.** 소문자 글리프가 없다.
> 6절의 화면 문구가 모두 대문자인 이유가 이것이다.

## 5. 상태머신 📊

```
        [전원 투입]
             |
             v
    +------------------+  EEPROM 무효 시 "NOT TRAINED" 표시
    |      IDLE        |
    +------------------+
       |            |
   짧게|            |길게(2초)
       v            v
  +---------+   +------------------+
  |MEASURING|   |  LEARN (n/3)     |<--+
  | DARK    |   |  시료 안내       |   |
  | R G B   |   +------------------+   | 다음 시료
  +---------+       | 짧게             |
       |            v                  |
       v        +----------+           |
  +---------+   |LEARN_RUN |-----------+
  | RESULT  |   | 8회 평균 |
  +---------+   +----------+
       | 짧게       | (3종 완료)
       |            v
       |        +---------+
       +------->|  SAVED  |--> IDLE
                +---------+

  TIMEOUT 발생 -> [ERROR] -> 짧게 -> IDLE
  LEARN 중 길게 -> 취소, IDLE (EEPROM 불변)
```

### 5.1 버튼 판정 규칙 🟡

| 조작 | 기준 |
|---|---|
| 짧게 | 20ms ~ 2초 누른 뒤 **떼었을 때** 발동 |
| 길게 | 2초 이상 누르면 **떼기 전에 즉시** 발동 |

길게가 떼기 전에 발동하는 이유: 사용자가 화면 안내(`HOLD BTN 2S`)를 보고
언제 손을 떼도 되는지 알 수 있어야 한다.

### 5.2 반복 측정 횟수

```c
#define MEASURE_REPEAT  3   /* 일반 측정 — 채널당 3회 평균 */
#define LEARN_REPEAT    8   /* 학습 — 채널당 8회 평균 */
```

학습 시 횟수를 늘린 이유: 기준점이 흔들리면 이후 **모든** 판정이 어긋난다.

두 값 모두 **Phase 1의 재현성(CV) 측정 후 조정할 값**이므로 상수로 분리한다.

## 6. 화면 설계 🟡

0.96" SSD1306, 6×8 폰트 기준 **가로 21자 × 세로 8줄**. 전부 대문자.

**IDLE — 학습 완료 상태**
```
LED PEDD ANALYZER
---------------------
READY

SHORT: MEASURE
LONG : LEARN
```

**IDLE — 학습 전**
```
LED PEDD ANALYZER
---------------------
NOT TRAINED

HOLD BTN 2S TO LEARN
```

**MEASURING**
```
MEASURING...
---------------------


DARK   R    G    B
 -     OK   -    -
```
채널이 끝날 때마다 `-` 가 `OK`(정상) 또는 `XX`(타임아웃)로 바뀐다.

화면 갱신은 **PB5 타이밍 펄스 바깥**에서 한다. I²C 통신 시간이 펄스 폭에
섞이면 사이클 처리 시간이 부풀려지기 때문이다. 펄스는 채널마다 따로
올렸다 내리고, 오실로스코프로는 4개 펄스의 폭을 합산해 읽는다.

**RESULT**
```
RESULT:  MILK
---------------------
R      1204 US
G       980 US
B      1510 US
DARK 206440 US
DIST 12 / THR 40
```

**LEARN 안내**
```
LEARN 1/3
---------------------
PUT DISTILLED WATER

SHORT: MEASURE
LONG : CANCEL
```

**LEARN 진행**
```
LEARNING
---------------------
DISTILLED WATER

DARK   R    G    B
 OK    OK   -    -
```
MEASURING과 같은 진행 표시를 쓴다. 반복 횟수(`SAMPLE 5/8`)는 표시하지 않는다 —
채널당 8회를 도는 동안 화면을 갱신하면 그 I²C 시간이 측정 사이에 끼어들어
조건이 일반 측정과 달라지기 때문이다. 진행 단위는 채널로 통일한다.

**SAVED**
```
SAVED TO EEPROM
---------------------
3 CLASSES STORED
```

**ERROR**
```
ERROR
---------------------
TIMEOUT: R

CHECK LED POLARITY
SHORT: BACK
```

### 6.1 시료 이름 🟡

| 내부 인덱스 | 화면 표기 | 시료 |
|---|---|---|
| 0 | `DISTILLED WATER` | 증류수 |
| 1 | `DYE WATER` | 식용색소 착색수 |
| 2 | `MILK` | 희석 우유 |
| — | `UNKNOWN` | 임계값 초과 |

## 7. 수치 파이프라인

전 구간 **32비트 정수**로 처리한다. `float`를 쓰지 않으므로 소프트웨어
부동소수점 라이브러리(약 1.5~3KB Flash)가 링크되지 않는다.

### 7.1 입력 범위

`pedd_measure()`는 틱 단위 방전 시간을 반환한다 (1틱 = 500ns).
`TIMEOUT_OVF = 61`이므로 상한은 다음과 같다.

```
t_max = 61 × 65536 = 3,997,696 틱 ≈ 2.0초
t_min ≈ 100 틱 (50µs)  — 광량이 매우 클 때
```

### 7.2 계산 단계와 오버플로우 검증

광전류는 방전 시간의 역수에 비례한다. 상수 `K = 1,000,000,000`을 쓴다.

**① 컨덕턴스**
```
G_ch = K / t_ch
```
| | t | G |
|---|---:|---:|
| 최소 t | 100 | 10,000,000 |
| 최대 t | 3,997,696 | 250 |

→ 최대 1.0e7. `uint32_t` 상한 4.29e9 대비 여유 충분.

**② 암전류 보정**
```
I_ch = G_ch - G_DARK      (음수면 0으로 클램프)
```
`G_DARK`는 t가 크므로 작다 (예: t=412,880 → G=2,422).
→ `I_ch` 최대 1.0e7.

**③ 정규화 — 합이 1000이 되도록**

순진하게 `I_ch × 1000 / sum` 을 계산하면 1.0e7 × 1000 = **1.0e10 으로
32비트를 넘는다.**

먼저 떠오르는 회피책은 나눗셈을 앞세우는 것(`divisor = sum/1000` 후
`I_ch / divisor`)인데, **이건 틀린다.** `sum`이 작을 때 정수 나눗셈이
잘려서 `divisor`가 0이나 1이 되고, 정규화가 성립하지 않는다.
예를 들어 `sum = 1999`이면 `divisor = 1`이 되어 `n_ch`가 최대 1999까지
나온다 — 합이 1000이 되어야 한다는 전제가 깨진다.

**대신 곱셈이 안전해질 때까지 먼저 우측 시프트한다.**

```
sum = I_R + I_G + I_B                    최대 3.0e7

if (sum < MIN_SIGNAL) → UNKNOWN          (신호 부족, 9절)

while (sum > 4,000,000) {                 최대 3회 반복
    I_R >>= 1;  I_G >>= 1;  I_B >>= 1;  sum >>= 1;
}

n_ch = (I_ch × 1000) / sum                결과 0~1000
```

**안전성 검증:** 시프트 후 `sum ≤ 4.0e6`이고 `I_ch ≤ sum`이므로
`I_ch × 1000 ≤ 4.0e9 < 4.295e9`(uint32 상한). 반복 횟수는 3.0e7에서
시작해 3회면 3.75e6이 되므로 최대 3회다.

시프트는 세 채널에 **동일하게** 적용되므로 채널 간 비율(=지문)은 보존된다.
버리는 것은 하위 비트뿐이고, 최종 해상도가 1/1000이라 영향이 없다.

**④ 제곱 유클리드 거리**
```
d2 = Σ (n_ch - c_ch)²
```
`n`, `c` 모두 0~1000이므로 차이는 최대 1000, 제곱 1.0e6, 3채널 합 3.0e6.
→ `uint32_t` 안전. **제곱근을 계산하지 않으므로** 정수만으로 비교가 끝난다.

**⑤ 판정**
```
가장 작은 d2 를 가진 클래스를 선택
d2 > THRESHOLD_D2 이면 UNKNOWN
```

화면의 `DIST`는 보기 좋도록 `d2`가 아니라 근사 거리를 표시한다
(정수 제곱근, 반복 8회 뉴턴법 — 코드 30바이트 수준).

### 7.3 임계값

```c
#define THRESHOLD_D2  1600   /* 거리 40에 해당. 실험 후 조정 */
```

**실험 전에는 적정값을 알 수 없다.** Phase 1~2에서 같은 시료를 반복 측정했을 때
지문이 얼마나 흩어지는지(클래스 내 분산)를 보고 정한다. 상수로 분리한다.

## 8. EEPROM 배치

ATmega328P EEPROM 1024바이트 중 **26바이트**만 사용한다.
`avr-libc`의 `eeprom_*` 함수 대신 **EECR / EEDR / EEARH / EEARL 레지스터를
직접 제어**한다. 요강의 "레지스터 직접 read/write에 높은 배점" 취지에 맞춘다.

| 주소 | 크기 | 내용 |
|---:|---:|---|
| 0 | 2 | 매직 넘버 `0x5044` — 유효성 표식 |
| 2 | 1 | 레이아웃 버전 (현재 1) |
| 3 | 1 | 클래스 수 (3) |
| 4 | 18 | 중심점 3클래스 × 3채널 × `uint16` |
| 22 | 2 | 임계값 `THRESHOLD_D2` |
| 24 | 2 | 체크섬 (앞 24바이트 합) |

**읽기 시 매직·버전·체크섬을 모두 검사한다.** 하나라도 어긋나면 학습되지
않은 것으로 간주하고 IDLE에서 `NOT TRAINED`를 띄운다. 공장 출하 상태의
EEPROM은 전부 `0xFF`라 자연스럽게 무효로 걸러진다.

**쓰기는 3종이 모두 모인 뒤 한 번에 수행한다.** 학습 도중 취소하면 기존
데이터가 보존된다.

## 9. 에러 처리

| 상황 | 감지 | 동작 |
|---|---|---|
| 채널 `PEDD_TIMEOUT` | `pedd_measure()` 반환값 | ERROR 화면에 **채널 이름 표시** |
| 신호 부족 (`sum < MIN_SIGNAL`) | 정규화 직전 | UNKNOWN 판정 |
| EEPROM 무효 | 매직/버전/체크섬 | `NOT TRAINED` |
| OLED 무응답 | TWI ACK 없음 | **UART로만 계속 동작**, 화면은 포기 |

마지막 항목이 중요하다. OLED 배선이 잘못돼도 **측정 자체는 계속되고 UART
로그는 나와야 한다.** 실험 도중 디스플레이 문제로 데이터 수집이 멈추면 안 된다.

TIMEOUT 시 채널 이름을 보여주는 이유는 `firmware/README.md` 5절에 있다 —
특정 채널만 TIMEOUT이면 검출 LED 색상 문제, 전 채널이면 극성 또는 광량
문제로 원인이 갈린다.

| **합계** | **~4.2 KB (13%)** | **~180 B (9%)** |

**검증 방법: 빌드하면 실제 숫자가 나온다.** 12~18% 범위를 크게 벗어나면
설계나 구현에 문제가 있다는 신호다.

참고로 현재: blink 0.5%, phase1 4.4%, phase2 4.2%.

## 11. 검증 계획

### 11.1 하드웨어 없이 (지금 가능)

1. **빌드 검증** — `PEDD.atsln`에 `phase4` 프로젝트를 추가해 컴파일 통과 확인
2. **메모리 확인** — 10절 예산과 대조
3. **`classify` 로직 검증** — 순수 계산 모듈이므로 PC에서 같은 입력을 넣어
   손계산 결과와 일치하는지 확인한다. 오버플로우 경계값(t=100, t=3,997,696,
   sum<1000)을 반드시 포함한다

### 11.2 부품 도착 후 — 단계별 브링업

**순서를 지키는 것이 중요하다.** 한 번에 다 연결하면 어디가 문제인지 모른다.

| 순서 | 확인 대상 | 통과 조건 |
|---|---|---|
| 1 | `01_blink` 업로드 | 보드 LED 1초 점멸 |
| 2 | 버튼만 연결 | 누르면 UART로 `SHORT`/`LONG` 출력 |
| 3 | OLED만 연결 | 화면에 `LED PEDD ANALYZER` 표시 |
| 4 | LED 4개 연결 | `02_phase1` 측정값이 나옴 |
| 5 | 전체 통합 | Phase 4 상태머신 전 구간 |

> OLED 모듈의 I²C 주소는 대개 `0x3C`이나 `0x3D`인 제품도 있다.
> 3단계에서 화면이 안 나오면 주소를 바꿔 시도한다. 상수로 분리해둔다.

### 11.3 성능 평가 (계획서 4.4.3절)

- 분류 정확도 + 혼동표 — 학습에 쓰지 않은 검증 시료로
- 채널별 재현성 CV
- Flash / SRAM / EEPROM 사용량 — 빌드 화면 캡처
- 1회 사이클 처리 시간 — PB5 펄스 폭을 오실로스코프로 측정
- TIMEOUT 및 이상값 발생 빈도

## 12. 실험 후 확정할 항목

설계 시점에 값을 알 수 없어 상수로 분리해둔 것들. **Phase 1~2 데이터가
나온 뒤 채운다.**

| 상수 | 초기값 | 근거가 될 데이터 |
|---|---|---|
| `THRESHOLD_D2` | 1600 | 클래스 내 분산 |
| `MIN_SIGNAL` | 3000 | 암실·차광 시 실제 `sum` 값 |
| `MEASURE_REPEAT` | 3 | 재현성 CV |
| `LEARN_REPEAT` | 8 | 재현성 CV |
| `K` (스케일 상수) | 1e9 | 실제 t 분포 |
| OLED I²C 주소 | 0x3C | 실물 모듈 |

`MIN_SIGNAL`은 "빛이 사실상 안 들어온다"고 볼 하한이다. 초기값 3000은
채널당 평균 1000에 해당하며, Phase 1에서 광 경로를 완전히 차단했을 때의
실제 `sum` 값을 보고 조정한다.
